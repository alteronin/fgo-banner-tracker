# Skill: Gacha Game Banner Data Model

## When to Use
Building a banner tracker for any gacha game (FGO, Genshin, HSR, ZZZ, WuWa, etc.). This is the domain-specific data schema and scraping approach.

## Data Schema

### Banner
```typescript
interface Banner {
  id: string;           // slugified name
  name: string;         // display name
  imageUrl: string;     // banner image URL
  startDate: string;    // YYYY-MM-DD
  endDate: string;      // YYYY-MM-DD
  servants: Servant[];  // rate-up characters
}
```

### Servant (banner entry)
```typescript
interface Servant {
  name: string;         // display name
  slug: string;         // URL-safe identifier
  rateUpType: "single" | "shared";  // rate-up type
}
```

### Servant (global collection)
```typescript
interface ServantData {
  slug: string;         // URL-safe identifier (matches banner servant slug)
  name: string;         // display name
  iconUrl: string;      // thumbnail image URL
  className: string;    // character class/element/type
}
```

### User Status
```typescript
type ServantStatus = "none" | "owned" | "planning";
type FilterOption = "all" | "owned" | "planning" | "either";
```

## Scraping Approach

### Banner Data
1. Fetch banner list page (HTML)
2. Parse with cheerio — look for table rows, card elements
3. Extract: name, image URL, start/end dates, servant list
4. Use region-specific dates (e.g., JP dates for JP server)
5. Sort by date descending

### Servant Data
1. Fetch sitemap for complete URL list
2. Fetch individual pages for details (icon, class, rarity)
3. Extract icon from `og:image` meta tag
4. Cross-reference slugs between banner servants and global list

### Image URLs
- External hosting (e.g., mana.wiki) — use ImageWithFallback
- Encode special chars: `[` → `%5B`, `]` → `%5D`
- Standardize query params: `?width=80` for icons, `?width=480&height=173` for banners

## Storage Pattern
- `src/data/banners.json` — all banners (static, regenerated by scraper)
- `src/data/servants.json` — all servants with icons (static, regenerated by scraper)
- `localStorage` — user's owned/planning status (per-servant)
- React Context — global state management for statuses

## Filtering Logic
```typescript
// Client-side filtering with useMemo
const filtered = useMemo(() => {
  let result = allBanners;
  if (filter === "owned") result = result.filter(b => b.servants.some(s => getStatus(s.slug) === "owned"));
  if (filter === "planning") result = result.filter(b => b.servants.some(s => getStatus(s.slug) === "planning"));
  if (search) result = result.filter(b => b.name.toLowerCase().includes(search.toLowerCase()));
  if (year) result = result.filter(b => b.startDate.startsWith(year));
  return result;
}, [allBanners, filter, search, year, getStatus]);
```

## Game-Specific Adaptations

### FGO (Fate/Grand Order)
- Classes: Saber, Archer, Lancer, Rider, Caster, Assassin, Berserker, Ruler, Moon Cancer, Alter Ego, Foreigner, Shielder, Pretender
- Rate-up types: Single (featured), Shared (multi-servant banner)
- Source: GamePress wiki (grandorder.gamepress.gg)

### Genshin Impact / HSR
- Elements: Pyro, Hydro, Anemo, Electro, Dendro, Cryo, Geo
- Rarity: 4-star, 5-star
- Source: Honey Hunter, Paimon.moe, or official APIs

### ZZZ / WuWa
- Element/type systems vary
- Check for official APIs before scraping

## Multi-Game Expansion
To support multiple games:
1. Add `game` field to Banner and ServantData
2. Create game-specific scrapers in `scripts/`
3. Store in separate JSON files: `banners-fgo.json`, `banners-genshin.json`
4. Add game selector UI component
5. Filter by game in the banner list
